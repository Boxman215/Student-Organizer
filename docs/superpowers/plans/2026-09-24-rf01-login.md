# RF01 - Plan de implementación del inicio de sesión

> **Para quien implemente:** seguir las tareas en orden. Cada tarea termina con una prueba y un avance separado. No agregar funciones de calificaciones, tareas ni promedio en esta rama.

**Objetivo:** Construir un inicio de sesión sencillo y funcional para Student Organizer, siguiendo el UML de la Entrega 2.

**Forma de trabajo:** Crear las clases del modelo, guardar usuarios en un archivo, revisar las credenciales desde el controlador y conectarlo a una ventana sencilla en español.

**Tecnología:** Java estándar y Swing, sin bibliotecas externas. Los usuarios se guardarán en `data/usuarios.csv`.

**Especificación:** `docs/superpowers/specs/2026-09-24-rf01-login-design.md`

## Reglas generales

- Mantener los nombres del UML: `Usuario`, `PersistenciaDatos`, `ControladorLogin` y `Vista`.
- Mantener el código, mensajes de pantalla y documentación en español.
- No guardar contraseñas directamente; guardar un código generado a partir de ellas.
- No agregar requisitos de otros integrantes.
- Dejar en la documentación los apartados para horas, contribuciones y muestra.
- Se necesita JDK 8 o superior para compilar y ejecutar. En este equipo todavía no están disponibles `java` ni `javac`, por lo que la prueba final se hará después de instalar o seleccionar un JDK.

## Enfoque de revisión

- Usuario y contraseña vacíos: mostrar un mensaje y no iniciar sesión.
- Usuario inexistente o contraseña incorrecta: rechazar el acceso y mantener la sesión vacía.
- Archivo inexistente: crear la carpeta y el archivo sin cerrar la aplicación inesperadamente.
- Línea dañada en el archivo: ignorarla y conservar los usuarios válidos.
- Cierre de sesión: borrar el usuario actual.

**Interfaces:**

- `String getNombreUsuario()`
- `String getContrasena()`

- `void setContrasena(String contrasena)`

- `String toString()`

- `PersistenciaDatos(Path rutaUsuarios)` para las pruebas
- `List<Usuario> leerUsuarios()`

- [ ] **Paso 1: Escribir la prueba que debe fallar**

```java
Path archivo = Files.createTempFile("usuarios", ".csv");
PersistenciaDatos persistencia = new PersistenciaDatos(archivo);
Usuario usuario = new Usuario("demo", "demo123", "0000");

persistencia.guardarUsuario(usuario);
List<Usuario> usuarios = persistencia.leerUsuarios();

assert usuarios.size() == 1;
assert usuarios.get(0).autenticar("demo", "demo123");
```

- [ ] **Paso 2: Ejecutar la prueba y confirmar que falla**

Ejecutar:

```powershell

```

Resultado esperado: falla porque las clases todavía no existen.

- [ ] **Paso 3: Crear la implementación mínima**

`Usuario` tendrá los tres atributos del UML. `Seguridad` convertirá la contraseña a SHA-256. `PersistenciaDatos` guardará cada usuario en una línea con el formato:

```text
nombreUsuario;contrasenaCodificada;carne
```

El archivo se creará automáticamente si no existe. Las líneas que no tengan tres partes se ignorarán.

Ejecutar los mismos comandos anteriores. Resultado esperado: `PruebasUsuarios` termina sin errores.

- [ ] **Paso 5: Guardar el avance**

```powershell

git commit -m "feat: agregar usuario y guardado de usuarios"
```

Este será el primer avance que se podrá subir a la rama.

### Task 2: Crear el controlador del inicio de sesión

**Archivos:**

- Crear: `src/controlador/ControladorLogin.java`
- Crear: `pruebas/PruebasLogin.java`

**Interfaces:**

- `ControladorLogin()`
- `boolean iniciarSesion(String usuario, String contrasena)`
- `void cerrarSesion()`
- `Usuario getUsuarioActual()`
- `String toString()`

- [ ] **Paso 1: Escribir las pruebas de los casos principales**

```java
ControladorLogin controlador = new ControladorLogin();

assert !controlador.iniciarSesion("", "");
assert !controlador.iniciarSesion("noExiste", "123");
assert !controlador.iniciarSesion("demo", "incorrecta");
assert controlador.iniciarSesion("demo", "demo123");
assert controlador.getUsuarioActual() != null;

controlador.cerrarSesion();
assert controlador.getUsuarioActual() == null;
```

- [ ] **Paso 2: Ejecutar las pruebas y confirmar que fallan**

Compilar las clases de la Tarea 1 junto con `pruebas/PruebasLogin.java`. Resultado esperado: falla porque `ControladorLogin` todavía no existe.

- [ ] **Paso 3: Crear la implementación mínima**

El controlador cargará los usuarios mediante `PersistenciaDatos`, rechazará campos vacíos, buscará el usuario y guardará el usuario encontrado en `usuarioActual`. No mostrará ventanas ni imprimirá mensajes; la pantalla se encargará de eso.

- [ ] **Paso 4: Ejecutar todas las pruebas**

```powershell

java -ea -cp salida PruebasUsuarios
java -ea -cp salida PruebasLogin
```

Resultado esperado: las dos pruebas terminan sin errores.

- [ ] **Paso 5: Guardar el avance**

```powershell

git commit -m "feat: agregar logica del inicio de sesion"
```

### Task 3: Conectar el Login con la pantalla

**Archivos:**

- Crear: `src/vista/Vista.java`
- Crear: `src/Main.java`

**Interfaces:**

- `Vista(ControladorLogin controladorLogin)`
- `void mostrarLogin()`
- `void mostrarMensaje(String mensaje)`
- `Main.main(String[] args)`

- [ ] **Paso 1: Crear la ventana mínima**

La ventana tendrá etiquetas y campos para `Usuario` y `Contraseña`, además del botón `Iniciar sesión`. Todos los textos estarán en español.

- [ ] **Paso 2: Conectar el botón al controlador**

Al presionar el botón, la vista enviará los valores a `iniciarSesion`. Si funciona, mostrará `Inicio de sesión correcto`; si falla, mostrará `Usuario o contraseña incorrectos` o `Complete todos los campos`.

- [ ] **Paso 3: Agregar el punto de inicio**

`Main` ejecutará `new Vista(new ControladorLogin()).mostrarLogin()` usando el hilo de eventos de Swing.

- [ ] **Paso 4: Ejecutar la prueba manual**

```powershell
java -cp salida Main
```

Comprobar el acceso con `demo` y `demo123`, una contraseña incorrecta y campos vacíos.

- [ ] **Paso 5: Guardar el avance**

```powershell
git add src
git commit -m "feat: conectar la pantalla del inicio de sesion"
```
